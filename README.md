# AgenticCIV6

> 让模型像老玩家一样算账，而不是背 wiki。

把《文明 6》的游戏数据编译成**可查询、可算账、可溯源**的决策知识库：模型这一轮拿什么数据、该算什么、缺什么，由契约决定，而不是由记忆决定。

它不绑定宿主——DeepSeek Harness 插件只是第一种接入方式；数据源当前是本地只读镜像，后续会换成游戏实时数据。两者都只替换外圈，核心不变。

## 它解决什么问题

- **记忆会漂移**：模型对"某个效果到底怎么算"的记忆不可信。这里每个效果都落成「官方文本 + 公式 + 出处」。
- **数字必须自洽**：成本、产出、回合由确定性算账给出，速度与时代口径随调用回显，不靠心算，也不做二次换算。
- **规则必须锁死**：一次会话只允许一套规则；库与规则对不上就拒绝启动，不降级成"凭记忆回答"。

## 亮点

- **不是百科，是契约**
  `civi6_instance` 只按硬约束出数据，一次给完一类；行内 `eff` 是权威文本、`fx` 是公式、`unres` 是未解析计数，另配 `gaps` / `omitted` 两张"这里没有"清单——"不知道"是显式答案，不是留白。

- **一描述一公式**
  构建期把每条 modifier 与每条表格效果落成 `scope + dimension + op + value (+ per + condition)`，描述由同一绑定渲染。文本与算法不可能各说一套；落不了行的逐条进审计，绝不编造。

- **确定性算账**
  `civi6_eval` 不取数，只做公式组合：供给 → 预算 → 缺口 → 砍单 → 低/基准/高三档情景。`speed` 必填，给需求侧时 `eraId` 必填，返回的 `basis` 回显成本倍数与回合压缩。

- **决策层而不是资料层**
  原始表回答"数值是多少"，`kb_*` 回答"走这条胜利线，某个时刻帝国该是什么状态"：计划带、时代检查点、文明特性带来的约束变换，都能一次查出。

- **fail-closed 溯源**
  规则身份、构建指纹、效果层时间戳逐项校验；缺效果层或规则不匹配直接拒绝服务。严格模式下命令直读数据库会被拦截，取数只能走工具。

- **可回归**
  `verify` / `verify:effects` / `kb:verify` 三套验证共 5 个脚本，加一个轨迹分析器；插件另有 39 个实体的回归夹具，把"必须一次答完"钉成断言。

- **轻**
  运行期零 npm 依赖（内置 `node:sqlite`），只读连接；构建管线只依赖一个 XML 解析器；TypeScript 源码用自带 loader 直跑，不引入打包器。

- **接入与数据源可替换**
  `dsh-plugin/index.js` 把查询、渲染与宿主适配分开导出；换宿主（游戏 Mod 等）或换数据源（游戏实时数据）时，实体 id、成本口径、包契约、公式层都不变。

## 状态与路线

- **当前**：内置两套规则库（标准规则 / BBG 覆盖），会话锁定 BBG 7.5.1（基于风云际会标准规则）；模型面 3 个工具、11 个数据类、五条胜利线的决策计划带。
- **下一步 · 接入方式扩展**：DSH 插件之外，规划游戏内 Mod 等接入；核心契约与查询逻辑不变。
- **下一步 · 数据源切换**：从构建期镜像库改为直接获取游戏实时数据；替换摄取与指纹，下游不变。

具体边界与不变量见 [架构方案 §10](docs/ARCHITECTURE.md)。

## 规则基线与许可

- 基线规则：**BBG 7.5.1（基于风云际会标准规则）**；标准规则库同时可用，但会话只能锁定其一。
- 游戏数据只读摄取，唯一写入位置是工作区 `data/`；BBG 源码为 MIT 许可，仅本地缓存，不随仓库分发。
- 环境变量与构建入口见 [`.env.example`](.env.example)。
